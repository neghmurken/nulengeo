## Specs
 - The **WHY**: @docs/functional-specs-fr.md
 - The **HOW**: @docs/technical-specs.md

## Do
 - Speak in English
 - Plan, ask and explain before starting any real work. Always wait for explicit user approval before editing anything
 - Always use interactive mode when asking questions
 - Follow existing architecture/pattern/convention instead of inventing new ones
 - Use existing libraries/frameworks
 - Use Taskfile commands for running anything
 - Always update both specs after adding/editing/removing something

## Don't
 - Don't take decisions alone, always ask for feedback
 - Don't overcomment, prefer self-explanatory code
 - Don't use `git` for anything else than reading/searching. Don't commit, don't push or pull, don't rebase, don't merge. Leave it to the user
